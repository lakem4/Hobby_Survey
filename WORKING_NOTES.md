### Non-obvious decisions

- **`Confirmation.tsx` uses `location.state`** — the survey form passes the raw `SurveyFormData` object via React Router `navigate("/confirmation", { state: form })`. If a user visits `/confirmation` directly (no state), the page renders a fallback message and a link back to the form. Do not change this to URL params — the data is too large and contains free text.
- **`dist/public` as outDir** — the extra `public` nesting is required so the Replit proxy can serve static files at the correct path. Azure SWA output location should be `dist/public` (relative to `artifacts/gym-survey`).
- **No backend API routes used** — this app talks directly to Supabase from the browser. The existing `artifacts/api-server` Express server is not used by this artifact.
- **All Radix UI / shadcn components removed** — the react-vite scaffold included ~50 pre-built UI components. They were all removed because this app uses plain HTML elements styled with Tailwind for full control over accessibility markup.

### Files / folders that must not be changed without discussion

- `public/staticwebapp.config.json` — required for Azure SWA routing; removing it will break all non-root routes in production
- `src/lib/supabase.ts` — throws on missing env vars intentionally; do not add silent fallbacks
- `vite.config.ts` — `BASE_PATH` and `PORT` fallback defaults are required for `pnpm build` to work without env vars in CI

## Data / Database

**Database:** Supabase (PostgreSQL), hosted externally. Credentials provided by developer via Replit Secrets.

### Table: `survey_responses`

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | BIGSERIAL | Yes (auto) | Primary key |
| `created_at` | TIMESTAMPTZ | Yes (auto) | Defaults to `now()` |
| `gym_frequency` | TEXT | Yes | One of: `daily`, `4-6`, `2-3`, `once`, `rarely` |
| `experience_rating` | TEXT | Yes | One of: `excellent`, `good`, `average`, `poor` |
| `frustrations` | TEXT[] | Yes | Array of: `crowded`, `wait`, `intimidating`, `guidance`, `dirty`, `other` |
| `frustrations_other` | TEXT | No | Free text; only present when `frustrations` includes `"other"` |
| `gym_time` | TEXT | Yes | One of: `early_morning`, `late_morning`, `afternoon`, `evening`, `night` |
| `gym_anxiety` | TEXT | Yes | One of: `yes_often`, `sometimes`, `rarely`, `never` |
| `biggest_challenge` | TEXT | Yes | Free-text answer |
| `improvements` | TEXT[] | Yes | Array of: `less_crowded`, `structured`, `smaller_groups`, `better_equipment`, `beginner_friendly` |

**RLS policies:** `anon` role can INSERT and SELECT. No UPDATE or DELETE policies exist. Individual rows are never exposed — the results page only reads aggregate counts client-side.

## Conventions

### Naming conventions

- **Files:** PascalCase for React components (`Survey.tsx`, `Footer.tsx`), camelCase for utilities (`supabase.ts`, `types.ts`)
- **CSS classes:** Tailwind utility classes only — no custom class names in component files
- **Supabase columns:** `snake_case` (e.g. `gym_frequency`, `experience_rating`)
- **TypeScript interfaces:** PascalCase, defined in `src/lib/types.ts` only — do not inline type definitions in page files

### Code style

- No default exports for utility functions — named exports only in `lib/`
- Default exports for all page and component files
- No `console.log` statements in committed code
- All form field IDs follow the pattern `field-{fieldName}` (e.g. `field-gymFrequency`)
- All error paragraph IDs follow the pattern `err-{fieldName}` (e.g. `err-gymFrequency`)
- Accent color is defined as the constant `ACCENT = "#8A3BDB"` at the top of each file that uses it — never hardcode hex values inline

### Framework patterns

- All routing via React Router DOM `<BrowserRouter>` with `basename={base}` (base comes from `import.meta.env.BASE_URL`)
- Supabase is called directly in page components — no custom hooks wrapping it yet
- Form state is plain `useState<SurveyFormData>` — no form library (react-hook-form was removed as unused)
- Validation runs on submit only, not on blur; errors are cleared per-field as the user makes changes

### Git commit style

Conventional Commits format:
```

chore: update dependencies

```

## Decisions and Tradeoffs

- **Direct Supabase calls from the frontend:** The app reads/writes Supabase directly from the browser using the anon key. This is intentional — the survey is fully public with no auth, and RLS policies restrict to insert + select only. Do not suggest moving this behind the Express API server.
- **Client-side aggregation on results page:** All rows are fetched and counted in the browser. This is acceptable for a course project with limited respondents. A Supabase RPC function would be better at scale, but adds complexity that is out of scope.
- **React Router DOM over Wouter:** The scaffold used Wouter. React Router DOM v7 was chosen for more predictable `location.state` passing to the confirmation page.
- **Plain HTML inputs over Radix UI / shadcn:** All scaffolded UI components were removed. Plain `<input>`, `<select>`, `<fieldset>`, and `<legend>` elements give full control over WCAG-compliant labelling and focus behaviour without fighting component abstractions.
- **`accentColor` CSS property for checkboxes/radios:** Native checkbox and radio inputs use `style={{ accentColor: ACCENT }}` — this is the simplest cross-browser way to theme them without a custom component.

## What Was Tried and Rejected

- **Shadcn/Radix UI components for form inputs** — removed because they made accessible labelling (`<legend>`, `<fieldset>`, `aria-describedby`) harder to control and added ~50 unused files to the scaffold. Do not suggest re-adding them.
- **Wouter for routing** — replaced with React Router DOM because `useLocation().state` behaviour on the confirmation page was more predictable with React Router. Do not suggest switching back.
- **react-hook-form** — was part of the scaffold, removed as unused. All validation is manual `useState`. Do not suggest adding it back unless the form grows significantly.
- **Hardcoded PORT/BASE_PATH throws in vite.config.ts** — original scaffold threw if these were missing. Changed to safe fallback defaults so `pnpm build` works in CI without injecting env vars. Do not revert to throwing behaviour.

## Known Issues and Workarounds

**Issue: "Other" frustration not shown in results charts**
The `frustrations_other` free-text column is saved correctly to Supabase but the results page only charts the fixed checkbox values. There is no workaround — it is simply not visualised yet.
Do not remove the `frustrations_other` insert/column — it stores real data.

**Issue: Results page fetches all rows**
`supabase.from("survey_responses").select(...)` returns every row. For a small course survey this is fine, but it will become slow at scale. No workaround in place. Do not "optimise" this prematurely — wait until there is an actual performance problem.

**Issue: Confirmation page breaks on direct URL visit**
Navigating directly to `/confirmation` without going through the form shows a fallback state (no response summary). This is by design — the state is passed via React Router and not persisted. The fallback UI is intentional and must remain.
